## 1.7.0 - 2026-10-11

- 2026-10-11: The safelight blush. Every irreversible call now reddens PART of the shell, in your theme's own `error` red, and how much says who can undo its effects (Bradley: "safelight shows for every irreversible call but not the full shell, partial shell would be a good thing here", "i like the growth on irreversibility", "who can undo sits well"). The rim alone: you can undo it yourself, now. The rim and the walls: undoing it does not get everything back. The rim, walls and top: nobody can undo it. The bubble says which, as `SAFELIGHT`, in words: what the call is and how it is undone. The whole creature stays red only for a write the witness holds, a write refused beneath, and the new haemorrhage; any of those wins over a blush. It lights as the call goes out and stays 8 seconds after the result, so a quick call is seen; a refused call clears it.
- 2026-10-11: The rung is read from what the call contains, not from the tool. A DROP, a TRUNCATE and a DELETE or UPDATE not pinned to one row lose rows: rung 3, or rung 2 when you set `pointInTimeRecovery` (unknown fails closed to 3). A one-row write with RETURNING is rung 1. A migration of only additive statements is rung 1; one destructive statement in it takes the destructive rung (the Ammonite's objection: a reverting migration restores the schema, not the rows a DROP took). A force push is rung 3; a plain push is rung 1, 2 when the ticket says the repo is metered, and 2 saying "not checked" when it says nothing. An outgoing email is rung 3. A filesystem delete, `git reset`, `git clean` and Notion writes are not read yet.
- 2026-10-11: The rung speaks about effects and never claims more than the witness can see (the Ammonite's second objection: undoing a row does not undo what a trigger on it sent). Every undo text ends with its source: "(metered register)", "(effectTables)" or "not checked". The new `effectTables` option lists tables whose writes can reach outside the database; a write to one is at least rung 2. A write to an unlisted table says its triggers are not in `effectTables`. The default list is empty.
- 2026-10-11: The haemorrhage. When an UPDATE or DELETE with RETURNING sends back far more rows than it named (more than it pinned, and more than `haemorrhageRows`, default 25), the whole creature goes red with `HAEMORRHAGE` and a bubble such as "675 rows came back from a statement that named 1". Display only; it lapses after 90 seconds or at your next prompt.
- 2026-10-11: The lamp test. At session start the whole creature shows red for 1.5 seconds, then clears, to prove the red channel works (`lampTest`, default on). New options: `pointInTimeRecovery`, `haemorrhageRows`, `lampTest`, `effectTables`. How the blush reads on the band at a small font, whether the lamp test draws, and the row count from a real result are a live look still owed.

## 1.2.0 - 2026-10-09

- 2026-10-09: The repair pair. A call that fails opens an antigen: the tool, the SQLSTATE (42703 undefined column, 42P01 undefined table, ...) or an error class, the target (table and column, a file, a Notion id) and the error's first line kept raw. The next call that succeeds on the same target is its cure, and the two are kept as one pair, with the diff between them (content, route, or none: weather) and an estimate of the tokens the failed attempts cost. Pairs are kept per project; an epitope that recurs becomes a hook or skill candidate at once, without a side pass. A guard's refusal followed by the identical call going through is marked autoimmune: a guard to retune. `/barnacles` lists the pairs under the barnacles, and the print gains a Repair pairs section.
- 2026-10-09: The sonar (userConfig `sonar`, `auto` by default: on where the ticket script is found). Each session writes a small heartbeat file every 30 seconds and reads the others'. `/pods` lists the other live sessions on the machine; the one line shows `pods N`, with `!K` in the warning colour while K files you both wrote in the last 30 minutes overlap in a shared place (the same repository, or the shared `~/.claude` rules, skills, tools and agents). A session that arrives in this repository is said once, and so is each overlap.
- 2026-10-09: Friction per session. Each session writes only its own friction, and every session reads them all, so with several sessions open in one repository none overwrites another's and the barnacles count all of it. A session's friction older than a day is folded into the project's archive.
- 2026-10-09: Carry-over per session. Each session keeps its leftover asks in a slot of its own, and a starting session takes only the leftovers of sessions that have ended (or gone quiet for six hours). With several sessions open in one repository, none inherits another's live asks any more, and none overwrites another's.
- 2026-10-09: Treat and wash in `/barnacles`. Treat puts the barnacle's evidence (its friction records, its repair pairs, what was already proposed) in the prompt box for the session to propose one fix; when you have accepted it and it has landed, the session's `treated` call takes the barnacle off, and a regrowth says the fix did not hold. Wash is the old scrub, for a false alarm.
- 2026-10-09: Wider pings. Writing a file inside another live session's repository tells both sessions; two sessions writing the same Notion page, or the same table by a direct statement, is an overlap too. Each kind is said in its own words, once per session.
- 2026-10-09: A hand left as a file (when a message could not be delivered) never starts a turn, whatever it says: it only waits in the prompt box, and one older than ten minutes is not taken. Claude's writes into the sonar's folder are refused in every session, the sonar on or off; reading a heartbeat is allowed. A pod number in `/hand` means the list you last saw in `/pods`.
- 2026-10-09: `/hand <pod> <what to do>` hands work to another live session. A hand you typed starts that session's turn once it is idle; a hand Claude writes (its new `hand` tool) lands in that session's prompt box and waits for your Enter, never over a draft. The receiving witness takes a hand only from another witness, and Claude cannot forge a typed one: its own messages may not carry the hand envelope and its file tools are refused in the sonar's folder.
